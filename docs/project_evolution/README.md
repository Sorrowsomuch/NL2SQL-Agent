# 项目演进文档

这个目录用于长期维护 DataAnalyze 的需求基线、系统现状、演进路线和关键架构决策，避免项目认知只散落在聊天记录里。

当前文档已经覆盖这些主题：
- 两段式 schema 获取
- schema 相关 helper 解耦
- 两阶段 planner
- 字段级知识接线
- query-aware 列保留
- 第一阶段 query planner 与第二阶段字段 planner

建议把这里当作“活文档”维护：
- `01_需求基线.md`
  记录项目目标、硬约束、当前产品诉求和验收边界。
- `02_系统现状与主链路.md`
  记录当前 `/chat` 主链路、模块职责和主要痛点。
- `03_演进路线图.md`
  记录已经完成的阶段、下一步重点和主线演进方向。
- `04_架构决策记录.md`
  记录为什么这样设计，以及为什么暂时不采用其他方案。
- `05_近期行动清单.md`
  记录最近几步最值得优先推进的工作项。
- `06_高风险整改记录.md`
  记录安全、护栏、审核规则等高风险问题的整改情况。
- `07_生产复杂查询推进路线图.md`
  记录从“当前可联调”走向“更接近生产复杂查询可用”的阶段路线。

维护约定：
- 每次进入一个新能力实现前，先同步“当前现状”和“近期行动”。
- 每完成一个阶段，至少更新 `03_演进路线图.md` 和 `05_近期行动清单.md`。
- 如果阶段内调整了设计取舍，同步更新 `04_架构决策记录.md`。
- 如果目标、约束或验收边界变化，同步更新 `01_需求基线.md`。
- 根目录下的 `implementation_stage_journal.md` 继续保留，主要承担按时间顺序回放每个阶段改了什么的作用。
