# 演进路线图

## 已完成阶段

### 阶段 1：结构化 schema 元数据层
- 把 schema 从字符串升级成结构化对象
- 保留旧接口兼容层

### 阶段 2：复杂查询底座与渐进式 schema 选择
- 引入候选表排序、关系扩展和 prompt 预算控制
- 让 executor 不再直接依赖整库 schema 字符串

### 阶段 3 起步：知识层与轻量检索
- 建立本地知识库目录结构
- 接入知识加载器、本地检索器和可选的 `bge-m3` embedding

### 阶段 3 补强：schema 获取与工程边界
- schema 元数据缓存与查询下推
- 两段式 schema 获取
- `postgres_schema_loader.py` / `schema_selection.py` 解耦
- 字段级知识接线与 query-aware 列保留
- 受约束的字段 planner

### 阶段 3 新补强：两阶段 Query Planner
- 新增第一阶段意图级 query planner
- 让候选表 hard/soft 规划前移到详细 schema 加载之前
- 保留第二阶段字段 planner，负责精确字段落地

## 2026-05-14 补充：Perfetto/output.pb MVP 阶段

### 已完成

- 新增 `PerfettoTool`，默认读取仓库根目录 `output.pb`。
- 新增 Perfetto SQL 只读护栏，保持和 PostgreSQL 查询链路类似的安全边界。
- 新增 `POST /perfetto/query`，用于直接执行 Perfetto SQL。
- 新增 `POST /perfetto/analyze`，用于模板化执行“性能问题 -> SQL -> 指标 -> 结论”闭环。
- 新增 Perfetto 分析响应模型：
  - `PerfettoAnalyzeRequest`
  - `PerfettoMetric`
  - `PerfettoAnalyzeResponse`
- 已跑通长耗时 slice 分析，能从 `output.pb` 返回 `dur_ms`、evidence 和初步 conclusion。

### 下一阶段

1. 扩充 Perfetto 模板库。
   - 主线程长任务。
   - CPU time TopN。
   - frame/jank 关联。
   - counter 趋势。
   - 线程调度延迟。

2. 把 Perfetto 模板知识沉淀到 `DataAnalyze/knowledge/perfetto/`。
   - tables
   - metrics
   - patterns
   - interpretation rules

3. 接入 agent 决策。
   - 识别用户问题是否属于 Perfetto trace 分析。
   - 在 `/chat` 或新的 agent 路由中选择 `PerfettoTool`。
   - 让 LLM 在模板候选范围内选择或改写 SQL，而不是无限制自由生成。

4. 增加 Perfetto Reviewer。
   - 检查 SQL 是否真的来自 Perfetto 查询。
   - 检查 ns/ms 单位转换。
   - 检查 conclusion 是否有 metrics/evidence 支撑。
   - 空结果需要区分“无异常”和“模板不适用”。

5. 预留 trace 入库能力。
   - 请求和响应结构中预留 `dataset_id` / `trace_id`。
   - 将当前固定 `output.pb` 抽象成默认 dataset。
   - 后续支持多份采集数据登记、查询和对比。
   - Agent 层不直接依赖文件路径，而是依赖 Perfetto 数据源接口。

6. 前端联调接口。
   - 保留 `POST /perfetto/agent` 作为后续前端接入入口。
   - 保留 `POST /perfetto/query` 作为 SQL 调试入口。
   - 保留 `POST /perfetto/analyze` 作为模板分析入口。
   - 后续新增 `GET /perfetto/datasets` 和 `POST /perfetto/datasets` 管理多份 trace。

### 阶段验收

- `/perfetto/query` 能稳定查询 `output.pb`。
- `/perfetto/analyze` 至少覆盖 5 类常见性能问题。
- 每个模板都返回稳定的 `sql / metrics / evidence / conclusion`。
- agent 接入后，Perfetto 分析不破坏原 PostgreSQL `/chat` 主链路。
- 前端可通过稳定接口传入 `problem` 和可选 `dataset_id`，不用关心底层是直接查 `output.pb` 还是查入库结果。

### 2026-05-14 已落地增量

- 新增 `POST /perfetto/agent`，作为前端主联调入口。
- 新增 `PerfettoAgentRequest` / `PerfettoAgentResponse` / `PerfettoReviewResult`。
- 新增 `PerfettoDataSource` 协议。
- 新增 `TraceProcessorPerfettoSource`，当前复用 `PerfettoTool`。
- 预留 `DatabasePerfettoSource`，用于后续已入库 trace 数据。

## 2026-05-14 补充：工具目录与 Perfetto Agent 落地状态

已完成一次工具层边界整理：

- 数据库工具迁入 `DataAnalyze/tools/db/`，保留现有 `DatabaseTool`、schema/planner/knowledge 能力，不改变 `/chat` 主链路。
- Perfetto 工具迁入 `DataAnalyze/tools/perfetto/`，形成 `PerfettoTool` 执行层、`perfetto_templates.py` 模板规划层、`perfetto_sources.py` 数据源边界层。
- `POST /perfetto/agent` 已作为前端主联调入口，当前默认 `source_type=trace_processor`，后续多 trace 对比、历史趋势、入库数据查询可切换到 `DatabasePerfettoSource`。

后续路线保持不变：单 trace 深挖先用 Trace Processor；多 trace 对比和历史趋势逐步走数据库抽取结果。
